Claude Code 마켓플레이스로 팀원에게 AI 도구 공유하기

우리 팀은 하나의 저장소에서 같은 일만 하지 않는다.

기획자, 프론트엔드 개발자, 백엔드 개발자가 여러 저장소를 오가며 일한다. 직군마다 다루는 코드와 도구는 다르지만 일감과 사내 문서 조회, Figma 명세 확인, PR 검토처럼 공통으로 반복하는 작업도 많았다.

이 작업을 위한 Claude Code 에이전트와 스킬을 각자 관리하면 같은 문제가 반복된다.

  • 같은 업무 규칙이 사람과 저장소마다 달라짐
  • 개선된 스킬을 팀원에게 다시 전달해야 함
  • 필요한 MCP와 인증 방법을 매번 설명해야 함
  • 직군별로 필요한 도구 조합이 다른데 한꺼번에 공유하게 됨

공통 에이전트와 스킬을 한곳에서 관리하고, 팀원이 필요한 것만 설치할 수 있는 배포 구조가 필요했다.

그래서 공용 Git 저장소를 만들고 Claude Code 플러그인 마켓플레이스로 배포했다.

마켓플레이스로 묶은 이유

Claude Code 마켓플레이스를 이용하면 팀원이 공용 저장소를 한 번 등록한 뒤 필요한 플러그인만 설치할 수 있다. 업데이트도 같은 저장소를 통해 전달된다.

여러 저장소와 직군의 공통 작업
  → 에이전트와 스킬로 정리
  → 업무별 플러그인으로 분리
  → 사내 Git 저장소에 등록
  → 팀원이 마켓플레이스에서 설치
  → 수정 후 버전을 올려 업데이트 배포

하나의 큰 플러그인 대신 실제 업무에 맞춰 세 가지로 나눴다.

플러그인 하는 일
업무 도구 일감, 댓글, 사내 문서, 기획 명세 조회
Figma 도구 시안 정보 추출, 코드 대조, 구현 계획 작성
리뷰 도구 PR 분석, 결함 후보 확인, 오탐 검증

각자 필요한 플러그인만 설치할 수 있어 불필요한 설정이 줄었다. 토큰과 OAuth 같은 인증 정보는 플러그인에 넣지 않고 사용자 환경에 따로 두었다. 공용 저장소에는 작업 절차만 들어가고 개인 경로나 계정 정보는 들어가지 않는다.

설치 후 바로 쓸 수 있게 함

설치만 된다고 끝은 아니었다. 팀원이 별도 명령을 외우지 않아도 평소처럼 요청하면 적절한 스킬이나 에이전트가 선택되도록 설명과 호출 조건을 정리했다.

"이 일감과 댓글 확인해줘"
"이 시안이랑 코드가 맞는지 봐줘"
"이 PR 리뷰해줘"

온보딩 문서에는 다음 내용을 한 흐름으로 넣었다.

  1. 마켓플레이스 등록과 플러그인 설치
  2. 필요한 MCP와 인증 설정
  3. 설치 확인과 첫 실행
  4. 자주 발생하는 오류와 해결 방법

실제로 팀원이 Windows에서 동작하지 않는 설치 명령과 잘못된 MCP 설명을 찾아 PR로 수정했다. 개인 환경에 맞춰져 있던 문서가 팀 전체에서 재현 가능한 설치 문서로 바뀐 순간이었다.

팀에서 쓰기 위한 최소 규칙

공유 범위가 넓어지면서 플러그인이 할 수 있는 일의 경계도 필요했다.

  • 조회와 분석은 자동으로 수행함
  • 댓글 등록처럼 외부 상태를 바꾸는 작업은 초안을 먼저 보여줌
  • 다른 사람의 PR에는 직접 push하지 않음
  • 토큰, 개인 경로, 계정 정보는 저장소에 넣지 않음
  • 스킬이나 에이전트가 바뀌면 플러그인 버전을 올림

PR 리뷰는 검토 에이전트의 판단을 그대로 사용하지 않았다. 별도의 검증 단계에서 결함 후보가 틀렸다는 증거부터 찾도록 했다.

PR 변경사항
  → 리뷰 에이전트가 결함 후보를 찾음
  → 검증 에이전트가 반증을 시도함
  → 근거가 남은 항목만 사용자에게 보여줌

오탐이나 실패가 발견되면 개인이 기억하는 데서 끝내지 않고 규칙을 고쳐 새 버전으로 배포했다. 이 과정은 이전에 정리한 AI 에이전트 피드백 루프를 팀 배포 구조로 옮긴 것에 가깝다.

공유 후 달라진 점

아직 “개발 속도가 몇 배 빨라졌다”라고 말할 데이터는 없다. 대신 다음 변화는 확인할 수 있었다.

  • 팀원이 같은 경로에서 같은 도구를 설치함
  • 업무 절차가 개인 프롬프트가 아니라 Git 변경 이력으로 남음
  • 수정 사항을 새 버전으로 한 번에 배포함
  • 다른 운영체제에서 발생한 문제가 팀원의 PR로 개선됨
  • Figma 검토와 PR 리뷰의 출력 형식이 통일됨

다음에는 온보딩에 걸리는 시간, 리뷰에서 실제로 유효했던 지적의 비율, 같은 문제로 다시 작업한 횟수를 측정해 볼 계획이다.

정리

Claude Code 설정을 팀에 공유할 때 중요한 것은 프롬프트 파일을 전달하는 일이 아니었다.

설치하고, 업데이트하고, 함께 수정할 수 있는 배포 구조가 필요했다.

마켓플레이스로 바꾼 뒤 개인 자동화는 팀원이 같은 방식으로 설치하고 개선할 수 있는 팀 도구가 되었다.
